K2E Model Architecture Explained

This page explains what K2E_Model_V2.py is doing, why it has multiple model layers, how the targets are built, and how to interpret the overall design. The script is not “one model.” It is a forecasting framework that compares several ways of modeling energy-market returns across gas, power, and carbon.

Markets

TTF Natural Gas, German Power, and EUA Emissions.

Horizons

Forecasts are produced for 1, 3, and 5 trading-day return horizons.

Model Philosophy

Start with a strong linear benchmark, then test whether regime-awareness or volatility-weighting materially improves it.

What Problem the Model Is Solving

The script models future cumulative log returns of major European energy assets. It is not trying to forecast levels directly first. Instead, it converts market prices into return series, builds explanatory features from market and physical-system variables, and predicts where returns will go over short future windows.

Forecast target = future returns Not just one market Multiple horizons

This is a sensible design for energy markets because gas, power, and carbon are tightly linked by weather, fuel substitution, infrastructure, storage, volatility, and policy shocks. A model that only sees price history would miss too much of the physical and economic system.

End-to-End Flow

1

Load Data

Reads either a .csv or Excel workbook. For Excel, it prefers sheet k2_clean and falls back to Data.

2

Engineer Features

Creates anomalies, seasonal splits, storage deviations, log returns, realized vol, coal-gas buffer features, and COT positioning variables.

3

Build Targets

For each market and horizon, constructs y as the forward cumulative log return over the next h days.

4

Train Layers

Fits four competing model families: baseline Ridge, volatility-switching Ridge, GARCH-weighted Ridge, and Markov-switching ARX.

5

Compare & Predict

Evaluates each model with expanding-window cross-validation, then optionally generates out-of-sample forecasts on new data.

Feature Families

Physical & Weather Signals

  • German and French temperature anomalies
  • Gas-consumption anomalies
  • Scandinavian water reservoir deviations
  • Wind, solar, and French nuclear generation
  • EU storage deviations from seasonal normal

Market & Fuel Signals

  • Lagged returns for TTF, power, EUA, coal, Brent, and JKM
  • Coal-gas switching support and resistance structure
  • Spot and prompt gas relationships
  • Realized volatility at 5-day and 20-day windows

Positioning & Regime Signals

  • COT net positioning and long/short ratios
  • Russian pipeline flow shock variables
  • Binary “no buffer” flags for broken switching ranges
  • Interaction terms like LR_COAL × NO_BUFFER

The Four Model Layers

Layer 1: Ridge-ARX Baseline

This is the benchmark. It standardizes the features, tunes the Ridge penalty over a small alpha grid, then fits a single linear model for each market/horizon pair.

  • Why Ridge? It handles many correlated predictors better than plain OLS.
  • Why ARX? It combines autoregressive lags with exogenous drivers.
  • Role in the stack: anchor model and feature selector for Layer 3.

Layer 2A: Vol-State Switching Ridge

This layer assumes the market is basically in one of two states: lower volatility or higher volatility. It splits the sample using the expanding 75th percentile of RVOL20, then trains a separate Ridge model in each state.

  • Idea: high-vol periods may obey different coefficients than calm periods.
  • Forecast rule: classify the current state, then use the matching Ridge model.
  • Limitation: only two states, and the split is imposed rather than learned.

Layer 2B: GARCH-Weighted Ridge

This layer still fits one linear model, but it reweights the training observations by inverse conditional volatility. Very turbulent observations get less influence on coefficient estimation.

  • Vol estimator: GARCH(1,1) if arch is installed, otherwise EWMA fallback.
  • Idea: stop crisis points from overwhelming the full-sample fit.
  • Role: robust version of Layer 1 rather than a fundamentally new structure.

Layer 3: Markov-Switching ARX

This is the most structural model. Instead of hard-coding a high/low volatility split, it lets the model infer hidden regimes directly from the data.

  • States: intended as normal, dual-stress, and gas-crisis regimes.
  • Feature control: only the top 5 Layer 1 features are used to keep estimation tractable.
  • Forecast rule: make state-specific predictions and average them using regime probabilities.

Why Layer 3 Uses Only Five Features

Markov-switching models get expensive and unstable quickly as the number of regressors grows. The code therefore selects the top 5 features from Layer 1 by absolute Ridge coefficient before fitting the regime model.

This means Layer 3 is not trying to beat Layer 1 by using more information. It is trying to beat Layer 1 by using different structure: state-specific relationships and endogenous regime detection.

How Validation Works

Expanding-Window CV

The code does not randomly shuffle the data. It uses expanding-window folds, which is the right idea for time series. Training always occurs on the past, testing on the future.

Metrics

  • CV RMSE: lower is better
  • Direction Accuracy: higher is better
  • Naive RMSE comparison: compares each model to a zero-return forecast benchmark

Important tradeoff

A model can win on RMSE and lose on direction accuracy, or vice versa. The script intentionally reports both because forecast quality depends on the use case.

How Prediction Works Out of Sample

When you pass --predict, the script appends the new data to the training history, re-engineers the features on the combined frame, and then generates forecasts only for the dates belonging to the new dataset.

  • L1: standardize with the stored scaler and predict with the fitted Ridge model.
  • L2A: compute the volatility state, then route each row through the low-vol or high-vol Ridge model.
  • L2B: use the weighted Ridge fit as a normal predictor at scoring time.
  • L3: compute state-specific predictions and combine them using the last smoothed regime probabilities from training.

What the Model Is Really Assuming

Economic Assumptions

  • Energy returns are partly predictable from short-run market memory.
  • Physical fundamentals such as storage, temperature, LNG, and generation matter.
  • Relationships are not fully stable through time.
  • Some instability comes from volatility shifts; some comes from deeper latent regimes.

Statistical Assumptions

  • Standardized linear effects are a useful first approximation.
  • Regularization is needed because many explanatory variables are correlated.
  • Time-series validation must preserve chronology.
  • Regime-switching estimation may be noisy, so the code uses restarts and can fall back from 3 states to 2.
The script is best thought of as a layered forecasting research platform: start with a disciplined baseline, stress-test it with volatility-aware variants, then ask whether hidden economic regimes genuinely improve the signal.

Short Summary You Can Reuse

K2E_Model_V2.py is a multi-layer short-horizon forecasting framework for TTF gas, German power, and EUA carbon returns. It transforms raw market and physical-system data into engineered features, predicts forward cumulative log returns at 1-, 3-, and 5-day horizons, and compares four model structures: a Ridge-ARX benchmark, a two-state volatility-switching Ridge, a GARCH-weighted Ridge, and a Markov-switching ARX that learns hidden regimes directly from the data.
